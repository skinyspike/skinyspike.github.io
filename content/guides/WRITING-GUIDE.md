# 가이드 집필 규칙

주간 자동 발행 루틴과 사람이 같은 기준으로 씁니다.
이 사이트의 가이드는 **애드센스 심사와 검색 신뢰도를 동시에 통과해야 하므로**,
분량보다 정확성과 실용성이 먼저입니다.

---

## 1. 파일 형식

`content/guides/<slug>.html` 한 파일에 meta 블록과 본문을 담습니다.
`<slug>` 는 영문 소문자와 하이픈만 씁니다. 짧을수록 좋습니다.

```html
<!--meta
{
  "title":       "검색해서 들어올 사람의 말로 쓴 제목",
  "description": "목록과 검색결과에 보이는 두 문장. 100~160자.",
  "category":    "반려동물 이동",
  "date":        "2026-11-13",
  "order":       7,
  "related":     ["pet-carrier-training", "pet-car-sickness"]
}
meta-->
<p>도입 문단</p>
```

| 필드 | 규칙 |
| --- | --- |
| `title` | 질문형이나 구체적 명사구. `~에 대하여` 같은 제목 금지 |
| `description` | 글 요약이 아니라 **읽을 이유**. 100~160자 |
| `category` | 아래 목록의 값만. 새로 만들려면 `tools/build.mjs` 의 `CATEGORY_ORDER` 에도 추가 |
| `date` | 발행일 `YYYY-MM-DD` |
| `order` | 같은 분류 안의 순서. 기존 최대값 + 1 |
| `related` | 이미 있는 다른 글의 slug 2~3개. 없는 slug 를 쓰면 무시됨 |

### 분류 목록

- `반려동물 이동` — 병원·이사·대중교통·차량 등 이동 자체
- `반려동물과 사는 일` — 건강·행동·돌봄 전반
- `아이 습관과 보상` — 습관 형성, 보상 설계, 가족 규칙

## 2. 구조

```
도입 2~3문단      독자가 겪는 장면 하나로 시작. 일반론 금지
<h2> 4~7개        각 섹션은 하나의 질문에 답한다
표 1~2개          비교·체크리스트·시간표는 반드시 표로
<div class="callout">  1~2개. 가장 중요한 한 가지
마무리            관련 글 1~2개로 연결
<div class="callout callout--warn">  해당하면 주의·면책
```

쓸 수 있는 마크업은 `p` `h2` `h3` `ul` `ol` `li` `strong` `em` `a` 와 아래 두 가지입니다.

```html
<div class="callout">강조 박스 (초록)</div>
<div class="callout callout--warn">주의·면책 박스 (노랑)</div>

<div class="table-wrap">
  <table class="table table--compact">
    <thead><tr><th>구분</th><th>내용</th></tr></thead>
    <tbody><tr><th>행 제목</th><td>값</td></tr></tbody>
  </table>
</div>
```

`<h1>` 은 쓰지 않습니다. 생성기가 제목에서 만듭니다.
`<img>` 는 쓰지 않습니다. 저작권이 확인된 이미지만 사람이 직접 넣습니다.

## 3. 분량

**태그를 걷어낸 본문이 3,000자 이상.** 2,500자 미만이면 발행하지 않습니다.
글자수를 채우려고 같은 말을 반복하는 것이 가장 나쁜 실패입니다.
분량이 안 나오면 주제가 좁은 것이니 범위를 넓히거나 다른 주제로 바꾸세요.

확인:

```bash
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8').replace(/<!--meta[\s\S]*?meta-->/,'').replace(/<[^>]*>/g,' ').replace(/\s+/g,' ').trim();console.log(s.length)" content/guides/<slug>.html
```

## 4. 문체

- **평서문, 단정적으로.** `~일 수도 있습니다` 를 남발하지 않습니다. 단, 사실이 불확실하면 그 사실을 명시합니다
- **독자를 `보호자`, `부모님` 으로 부릅니다.** `여러분` 금지
- **과장 금지.** `놀라운`, `완벽한`, `최고의` 같은 말을 쓰지 않습니다
- **섹션 제목은 내용을 말합니다.** `2. 주의사항` 이 아니라 `2. 금식 여부는 꼭 전화로 확인하세요`
- **문단은 3~4문장.** 긴 문단은 모바일에서 벽이 됩니다
- 기존 9편의 톤을 기준으로 삼으세요. 특히 `pet-hospital-checklist`, `positive-reinforcement`

## 5. 사실 관계 — 가장 중요한 부분

### 절대 하지 않는 것

- **통계·연구·수치를 지어내지 않습니다.** `연구에 따르면 73%가` 같은 문장은 출처를 확인하지 못하면 쓰지 않습니다
- **약 이름과 용량을 안내하지 않습니다.** `수의사와 상의할 영역` 으로 넘깁니다
- **진단하지 않습니다.** 증상에 병명을 붙이지 않고, 병원에 가야 하는 신호만 적습니다
- **법령 수치를 기억으로 쓰지 않습니다.** 반드시 확인하고, 확인 못 하면 수치를 빼고 확인 절차를 안내합니다
- **특정 상품·업체를 추천하지 않습니다.** 유형별 장단점까지만

### 출처가 엇갈릴 때

`pet-public-transport` 가 기준입니다. 블로그마다 숫자가 다른 사안은
**숫자를 적는 대신 "어디에 무엇을 물어야 하는지"를 적습니다.**
이게 틀린 숫자를 퍼뜨리는 것보다 독자에게 유용하고, 사이트 신뢰도에도 이롭습니다.

### 확인 방법

법령은 [국가법령정보센터](https://www.law.go.kr), 제도는 소관 부처,
운송·요금은 해당 사업자의 공식 안내를 봅니다.
웹 검색 결과가 블로그 2차 자료뿐이면 그 사실을 글에 밝히고 단정하지 않습니다.

### 면책 박스

건강·의료·법령·금전이 걸린 글은 마지막에 `callout--warn` 을 답니다.

```html
<div class="callout callout--warn">
  이 글은 ○○를 돕기 위한 자료이며 진료를 대신하지 않습니다.
  <strong>최종 판단은 담당 수의사의 안내를 따르세요.</strong>
</div>
```

## 6. 자사 언급

**글 하나에 최대 한 곳.** 맥락상 자연스러운 자리에만 둡니다.
`네발손님`, `패밀리 퀘스트`, `pricing.html` 링크가 해당합니다.

광고성 문장으로 끝내지 않습니다. 기존 글의 처리 방식을 보세요 —
`habit-two-weeks` 는 앱을 소개한 뒤 `앱이 없어도 이 2주 절차는 종이 한 장으로 충분히 돌아갑니다` 로 닫습니다.

홍보가 목적인 글은 가이드가 아니라 공지사항에 씁니다.

---

## 7. 내부 링크

- `related` 에 2~3개
- **본문 안에서도 1~2개** 를 자연스럽게 연결합니다. 주소는 `guide-<slug>.html`
- 이미 있는 글에서 새 글로 거는 링크는 추가하지 않습니다. 생성물을 손대야 해서 다음 빌드에 지워집니다

---

## 8. 발행

```bash
node tools/build.mjs
```

생성물(`guide-*.html`, `guide.html`, `notice*.html`, `sitemap.xml`)은 커밋에 포함합니다.
GitHub Pages 에는 빌드 과정이 없습니다.

- [ ] 약 용량·진단·상품 추천이 없음
- [ ] 필요한 글에 면책 박스가 있음
