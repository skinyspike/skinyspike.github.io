너는 wonderplant.xyz(주식회사 원더플랜트) 정적 사이트 저장소에서 **주간 가이드 한 편**을 작성하는 일을 맡았다. 지금 작업 디렉터리가 그 저장소다. 빌드 도구 없는 순수 정적 사이트이고, GitHub Pages 로 배포된다.

## 시작하기 전에 반드시 읽을 것 (순서대로)

1. `content/guides/WRITING-GUIDE.md` — 집필 규칙. **이 문서가 최우선 기준이다.** 아래 지시와 충돌하면 이 문서를 따른다.
2. `content/guides/BACKLOG.md` — 주제 대기열
3. `content/guides/pet-hospital-checklist.html` 와 `content/guides/positive-reinforcement.html` — 톤·구조의 기준 샘플. 반드시 통독한다.

## 할 일

**1. 주제 선택**

`BACKLOG.md` 의 '대기 중' 목록에서 **맨 위의 `- [ ]` 항목 하나**를 고른다. 아래쪽 항목을 임의로 고르지 않는다. 그 항목의 분류와 메모를 그대로 따른다.

대기열이 비어 있으면 **글을 쓰지 말고** 그 사실만 보고하고 끝낸다. 주제를 지어내지 않는다.

**2. 사실 확인**

주제에 법령·제도·수치·의학 정보가 들어가면 WebSearch 로 확인한다. WRITING-GUIDE.md 5장을 그대로 지킨다. 특히:

- 통계·연구·법령 수치를 기억에 의존해 쓰지 않는다. 확인하지 못하면 쓰지 않는다
- 출처마다 숫자가 엇갈리면 **숫자를 빼고 '어디에 무엇을 물어야 하는지'를 쓴다.** `content/guides/pet-public-transport.html` 이 그 방식의 예시다
- 약 이름·용량, 진단, 특정 상품·업체 추천은 쓰지 않는다
- 건강·의료·법령·금전이 걸린 글은 끝에 `callout--warn` 면책 박스를 단다

**3. 집필**

`content/guides/<slug>.html` 을 새로 만든다.

- `<slug>` 는 영문 소문자와 하이픈만. 짧게
- meta 블록 `date` 는 오늘 날짜. `date +%Y-%m-%d` 로 확인해서 쓴다
- `order` 는 같은 분류의 기존 최대값 + 1
- `related` 는 `content/guides/` 에 **실재하는** slug 2~3개. 없는 slug 를 쓰면 링크가 사라진다
- 본문 안에도 다른 가이드 링크를 1~2개 자연스럽게 넣는다 (주소는 `guide-<slug>.html`)
- 자사 언급(네발손님, 패밀리 퀘스트, pricing.html)은 **글 하나에 최대 한 곳**
- 태그를 걷어낸 본문이 **3,000자 이상**. WRITING-GUIDE.md 3장의 명령으로 직접 세어 확인하고, 2,500자 미만이면 내용을 보강한다. 같은 말을 반복해 글자수를 채우지 않는다

**4. 빌드**

```
node tools/build.mjs
```

오류가 나면 원인을 고치고 성공할 때까지 반복한다.

**5. 점검**

WRITING-GUIDE.md 9장의 체크리스트를 항목별로 확인한다.

**6. 백로그 갱신**

`BACKLOG.md` 에서 그 항목을 '대기 중'에서 지우고, '발행 완료' 맨 위에 다음 형식으로 추가한다.

```
- [x] 제목 — 분류: <분류> → `<slug>`
```

**7. 커밋 — 푸시는 하지 않는다**

`main` 브랜치에 **커밋만** 한다.

- 커밋 제목: `가이드 추가: <글 제목>`
- 본문에 한 줄 요약
- `content/guides/<slug>.html`, `content/guides/BACKLOG.md`, 그리고 생성물(`guide-*.html`, `guide.html`, `sitemap.xml`)을 모두 포함한다
- '대기 중' 항목이 5개 아래로 남았으면 커밋 본문에 `주제 백로그 잔여 N건 — 보충 필요` 를 덧붙인다

> **`git push` 를 실행하지 않는다.** 발행 여부는 사람이 글을 읽고 직접 결정한다.

**8. 슬랙 전송**

```
node tools/notify-slack.mjs <slug>
```

웹훅 주소는 환경변수 `WONDERPLANT_SLACK_WEBHOOK` 에서 읽는다.

- **웹훅 주소를 저장소 안 어떤 파일에도 적지 않는다.** 공개 저장소다. 주소를 출력하지도 않는다
- 전송이 실패해도 **작업을 되돌리지 않는다.** 글과 커밋은 그대로 두고, 실패 사유만 보고한다
- 환경변수가 없으면 그 사실을 보고하고 전송만 건너뛴다

## 하지 말 것

- `git push` — 어떤 경우에도 하지 않는다
- 기존 가이드 원고 수정 (새 글만 추가한다)
- `guide-*.html`, `guide.html`, `notice-*.html`, `notice.html`, `sitemap.xml` 직접 편집 — 전부 `tools/build.mjs` 가 만드는 생성물이다
- 이미지 추가 (저작권 확인이 안 된다)
- 저장소 구조, 스타일시트, 사이트 설정 변경
- 한 번에 두 편 이상 작성
